# Spec：代码审查修复 —— 正确性缺陷、稳定性收尾与测试基线

> 生成日期：2026-08-16
> 来源：对前端（Vue 3 + TypeScript）、Rust 后端与前后端契约的三路全量代码审查
> 前置：建立在《性能优化改动清单》（2026-08-09，已全部落地）之上；该清单第五节"已确认无需改动的部分"及本次复核确认正确的机制（攒批 emit、编译缓存、防抖落盘、generation counter 等）**不要误改**
> 状态：ready-for-agent

## Problem Statement

Mini MQTT Client 作为调试工具，其核心价值是"看到的就是真实发生的"。但当前存在一批破坏这一信任的正确性缺陷：

- 在多个 Server 之间切换时，发布和订阅可能用**另一个 Server 的环境变量**替换 `{{变量名}}`，调试者发出的内容与预期不符且无从察觉；
- 定时发布 HEX 类型模板时，十六进制字符串被当作普通文本编码发送，且消息列表还显示为 TEXT，掩盖了错误；
- 消息接收链路一旦出现一次未捕获异常，之后所有消息**静默不再显示**，直到重启应用；高频场景下每批消息在列表中的顺序还是颠倒的；
- 非当前查看的 Server 断线重连后订阅静默丢失——状态显示已连接，消息却不再到达；
- 修改脚本或环境变量后，旧版本最多还会继续生效 5 秒；
- 定时发布中预处理脚本失败时被静默忽略，未处理（例如未加密）的原始 payload 照常发出并计为成功；
- 退出应用的瞬间恰逢后台落盘，最后一次修改可能丢失；持久化持续失败（磁盘满等）时用户完全无感知；
- 非法的端口 / QoS / keep-alive 配置被静默截断，其中负的 keep-alive 会导致周期性掉线循环。

对维护者而言：项目**零测试**，存在两条平行的发布管线、三份行为不一致的变量替换实现、约 1600 行死代码和多处死链（前端调用不存在的后端命令、i18n 死键、未使用的依赖），每次改动的回归风险都靠人肉承担。

## Solution

一次系统性的修复与收尾：

1. **正确性**：环境变量按 Server 严格隔离；定时发布与手动发布走同一条管线（HEX 解码、脚本失败中止、写历史、UI 展示带类型）；接收链异常自动恢复、批内保序；任意 Server 重连后都自动恢复订阅；脚本/环境变量修改即时生效；退出可靠落盘；持久化失败界面可见。
2. **稳定性**：连接参数入口校验；重连过程状态事件不再乱序；断线期间发布立即报错而非假成功；超大入站消息给出明确提示而非无限重连循环；ID 计数器与数据自动校正。
3. **工程化**：建立 vitest（前端 store 层与纯函数）+ cargo test（Rust 存储与校验层）测试基线，优先覆盖本次全部修复点。
4. **清理**：发布管线、变量替换、编码工具各收敛为唯一实现；删除死代码、死命令、死键；依赖与 i18n 构建链路瘦身。

## User Stories

### 调试用户（正确性）

1. As 一个 MQTT 调试用户, I want 发布消息和添加订阅时 `{{变量名}}` 始终用当前 Server 的环境变量替换, so that 切换 Server 后不会把别的 Server 的变量值发出去。
2. As 一个 MQTT 调试用户, I want 定时发布 HEX 类型模板时 payload 按十六进制解码后发送, so that 定时发布与手动发布行为一致。
3. As 一个 MQTT 调试用户, I want 定时发出的消息在列表中显示正确的 payload 类型, so that 我能一眼核对实际发出的内容。
4. As 一个 MQTT 调试用户, I want 消息接收链路出现异常后自动恢复并继续显示后续消息, so that 一条坏消息不会让整个消息流静默死亡。
5. As 一个 MQTT 调试用户, I want 高频消息场景下列表严格按到达顺序显示（最新在上）, so that 我能依赖消息顺序做时序分析。
6. As 一个 MQTT 调试用户, I want 修改或启停脚本后立即对下一条消息生效, so that 调试脚本时不需要等待或重启。
7. As 一个 MQTT 调试用户, I want 修改环境变量后立即对发布、订阅和接收脚本生效, so that 变量改动的效果可以立刻验证。
8. As 一个 MQTT 调试用户, I want 任何已连接的 Server 断线重连后自动恢复其全部订阅（无论我当前正在查看哪个 Server）, so that 后台 Server 不会出现"显示已连接却收不到消息"。
9. As 一个 MQTT 调试用户, I want 切换当前查看的 Server 时不触发多余的重复订阅, so that broker 侧不会看到无意义的订阅风暴。
10. As 一个 MQTT 调试用户, I want 定时发布中预处理脚本失败时中止该条发送并计为失败, so that 未加密/未签名的原始内容不会被发上线。
11. As 一个 MQTT 调试用户, I want 退出应用时所有未落盘的修改被可靠保存, so that 关闭前的最后一次配置改动不会丢失。
12. As 一个 MQTT 调试用户, I want 配置数据持久化失败时收到界面提示, so that 磁盘满或路径失效时我能及时发现而不是默默丢数据。

## Implementation Decisions

以下决策均已在审查阶段读码确认可行。**不含具体文件路径**（易过期），按模块描述。

### 环境变量隔离（Story 1、7、24、29）

- 发布与订阅路径不再使用 env store 的全局变量列表做替换，统一改用 MQTT store 中**已按 Server 隔离、带 TTL 的环境变量缓存**（接收脚本路径现在用的就是它，行为正确）。
- env store 降级为环境变量管理抽屉（EnvDrawer）的 UI 数据源，不再充当替换数据源，消除双数据源。
- 环境变量 CRUD 成功后使相应 Server 的缓存失效（见"缓存失效"）。
- `{{变量名}}` 替换收敛为一份实现：单遍正则替换（变量值中出现的 `{{OTHER}}` 不做链式二次替换）、变量名做正则转义。脚本引擎暴露的 `env.replace` 委托这份实现。现有三份实现中删两份。
- 订阅 topic 的变量替换语义统一为**入库前替换**（与现有添加路径一致），编辑订阅路径补上同样的替换。

### 发布管线收敛（Story 2、3、10、28）

- 抽取统一的发布管线（composable），流程固定为五步：环境变量替换 → before_publish 脚本 → 按 payload 类型发布（HEX 在 Rust 侧解码，与手动发布现行为一致）→ 写发布历史 → UI 消息入队（携带 payload 类型）。
- 手动发布面板与定时发布对话框都调用该管线，各自只保留 UI 状态。
- 脚本抛错时管线中止该条发送、上报脚本错误、计为失败——与手动发布现行为对齐。

### 消息接收链路（Story 4、5）

- 接收串行链补上异常捕获：单条消息处理失败走统一错误处理后链继续，保证后续消息正常。
- 批量插入列表前将批内消息反转，维持"index 0 = 最新"的既有约定，消除批内锯齿乱序。

### 缓存失效（Story 6、7）

- 脚本 store 的创建/更新/删除/启停成功后，调用 MQTT store 已存在的脚本缓存失效接口（该接口目前是零调用的死接口，接上即可）；环境变量同理。

### 订阅恢复与连接状态（Story 8、9、16）

- 自动重订阅逻辑从 Header 组件迁移到 MQTT store 的连接状态事件监听中，按事件携带的 server_id 处理**任意** Server 的"→已连接"转变，不再依赖"当前活跃 Server"的派生状态。
- 由此同时消除"切换活跃 Server 造成假状态转变、触发重复订阅"的副作用。
- 连接状态事件携带连接代数（generation），或 Rust 侧 emit 前校验自身仍是当前代；前端丢弃旧代事件，消除重连时"disconnected 晚于 connected 到达"的乱序。

### Rust 存储层（Story 11、12、19、34）

- 退出时的 flush 改为**无条件落盘**（不检查脏标记），消除"后台线程已取走脏标记但尚未写完"窗口内退出丢数据的竞态；后台防抖机制本身保留不动。
- 数据加载完成后，各 ID 计数器按现有实体的最大 ID 校正，根除计数器归零导致的重复 ID。
- 持久化失败时向前端 emit 存储错误事件并写入日志，前端弹出提示；不再只打印到不可见的 stderr。
- update 类操作统一语义：目标 ID 不存在时返回错误、不置脏标记；更新 Server 时保留服务端原有的创建时间，不接受客户端覆盖。
- 原子写在 rename 前补 fsync。

### 参数校验（Story 13、14、15）

- 在 Server 与订阅的创建/更新命令入口统一校验：端口 1–65535、QoS 0–2、keep-alive 非负、host/topic 非空；**校验通过才持久化**（现状是先落库再报错，留脏数据）。
- 消除 keep-alive 负值经符号扩展进入连接参数的路径（该路径经与 rumqttc 0.24 源码比对确认会导致"客户端永不发 ping、broker 周期性踢线"）。

### 连接层健壮性（Story 17、18）

- 连接句柄维护真实连接状态标志（原子布尔，随连接事件更新）；断线/重连退避期间发布命令立即返回失败，不再静默入队。
- 入站包超过大小上限的错误识别为持久性错误：提示用户并停止对该错误的无限重连循环（其余瞬时错误维持现有指数退避）。

### 零散性能点（Story 20、21）

- 消息详情的 HEX 视图设行数上限（超出部分提示 + 按需加载或分页），消除数万 DOM 节点一次性渲染。
- 发布方向 payload 改为 base64 过 IPC（与接收方向 1.1 的改法对齐），Rust 发布命令相应改收 base64。
- 脚本编译缓存淘汰策略从"满员整表清空"改为删除最旧一条（Map 天然插入序）。
- 发布历史的 payload 采用与接收方向一致的截断策略，防止大 payload 反复发布导致常驻内存膨胀。
- 攒批 flush 定时器改为仅在批非空时挂起一次性定时器，消除空转唤醒。

### 脚本体验（Story 23、25）

- 现有的脚本语法校验函数改用 AsyncFunction 构造器（当前用同步 Function 会误报含顶层 await 的合法脚本），并接入脚本保存流程。
- 脚本导入入口增加一次性风险提示文案（不做沙箱改造，见 Out of Scope）。

### i18n 与文案（Story 22）

- 修复引用对象节点导致表头渲染为原始键名的问题（新增叶子键）。
- 错误标题映射、MQTT 错误映射表、脚本错误文案、"(副本)"后缀、固定 zh-CN 的时间格式化等硬编码文案迁入语言文件。
- 删除 32 个确认无引用的 i18n 死键（中英文键已对齐，保持对齐）。
- i18n 构建链路接入已安装未启用的 unplugin-vue-i18n：YAML 构建期预编译、启用 vue-i18n runtime-only、js-yaml 移出运行时依赖。

### 死代码与依赖清理（Story 31、32、33）

- 删除：无引用的模板组件链（模板管理器/模板列表/快捷发送面板）、独立的变量替换工具文件、server store 的死连接状态、MQTT store 只写不读的订阅 Map、message store 的死方法、防抖工具中的无引用函数。
- 删除前端对不存在的模板搜索命令的调用及对应 store 方法。
- 裁剪后端注册但前端从未调用的命令（逐个确认后删除）。
- Cargo 依赖清理：移除 thiserror（零使用）、tauri 的 tray-icon 特性（无 tray 代码）、chrono 的 serde 特性（未用）。
- base64/hex 编解码收敛为一份**严格**实现（奇数长度、非法字符报错），前端各处及脚本引擎委托之；发布前置校验补偶数长度检查。

## Testing Decisions

**接缝（已与开发者确认）**：两条，各为所在侧的最高可测点。

1. **前端：Pinia store 层**。vitest + `@vue/test-utils` 不需要；仅 `createPinia` + mock `@tauri-apps/api`（invoke / event 的 listen、emit）。测试通过"调用 store 方法 / 模拟后端事件 → 断言 store 公开状态与发往后端的调用参数"进行，不渲染组件、不测实现细节。
2. **Rust：Storage 与命令校验层**。`cargo test` + 临时目录构造 Storage 实例，直接测公开方法；校验逻辑独立成可测函数。

**什么是好测试**：只测外部可观察行为——store 的公开状态、invoke 出去的命令与参数、对模拟事件的反应、Storage 落盘后的文件内容与重新加载结果。不断言私有字段、内部调用次数或定时器实现。

**优先覆盖（与本次修复一一对应）**：

- 消息接收：批内/跨批保序、单条异常后链恢复、快路径与慢路径共存时不乱序
- 环境变量：按 Server 隔离（切换 Server 后替换值正确）、CRUD 后缓存立即失效
- 发布管线：HEX 解码路径、脚本失败中止且计为失败、payload 类型透传到 UI 消息
- 纯函数：topic 通配符匹配、变量替换（含转义与不二次替换）、错误聚合去重窗口、脚本编译缓存命中与失效、base64/hex 严格编解码边界
- Rust：退出 flush 无条件落盘（脏标记竞态场景）、ID 计数器校正、参数校验拒绝矩阵（端口/QoS/keep-alive/空值）、update 目标不存在返回错误、原子写与损坏备份恢复

**Prior art**：项目当前零测试，无先例可循。vitest 是 Vite 项目零成本选择；Rust 侧用标准 `#[cfg(test)]` 模块 + tempfile。本 spec 落地后这两处即成为后续测试的先例。

## Out of Scope

- **大型重构**：存储模块按实体拆分、侧边栏组件拆分、定时发布调度状态机抽取——审查确认值得做但不紧迫，另行立项。
- **脚本沙箱隔离**（Worker 化）：本次只加导入风险提示；沙箱改造涉及脚本 API 全面异步化，单独评估。
- **消息历史持久化**（append-only JSONL）：v1.6.0 已明确消息历史仅存内存，本次不改变该决策。
- **serde_yaml → serde_norway 迁移**：沿用性能清单中"可选、暂不做"的结论。
- **端到端测试**（tauri-driver）：投入产出比低，已在接缝讨论中排除。
- **CSP 收紧**：当前无 v-html、暴露面小，暂不处理。
- **vite 分包与构建目标调优**：中等收益，可随任意后续改动顺手做，不作为本 spec 的验收项。
